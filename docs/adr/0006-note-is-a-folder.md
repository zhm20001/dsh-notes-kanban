# 存储单位：一条笔记 = 一个目录（note.md 主文档 + 自由资产）

## Status

accepted（2026-08-20 与用户共同裁决：全部笔记统一目录化、主文档定名 `note.md`）

## 决策与背景

一条笔记在磁盘上是 **notes/ 下一个目录**，不再是一个 markdown 文件：

```
notes/
  <UTC时间戳>-<slug>-<4位随机>/   # 目录名 = 笔记 id（规则与旧文件名相同，去 .md）
    note.md                        # 主文档：front-matter + 正文——工具唯一读写的文件
    note.md.bak                    # 写前备份（单层，语义不变）
    <自由文件 / assets/…>           # 工具永不触碰；用户手动放置
```

**这是一次契约修正，不是新决策。** grill 阶段（spec 0001 的 Q10 问答）用户原话即是
"用文件夹来存"；当时的 AI 把它理解成「扁平单文件 + assets 括号」的并行方案，落成
spec 0001 L51 的"一条笔记一个 markdown 文件（+ `assets/` 放附件）"——那个括号是原始
意图的残留痕迹。因早期笔记都能用单文档描述，误读的方案一路落地未被发现。2026-08-20
用户回看记录后指出此节，本 ADR 回归原始意图并修订 spec 0001 L51 / ADR-0003 的存储条款。

理由（按重要性）：

- **项目天然超出单文档**：一个正在追究的主题（学习科目、项目）会长出多文档结构与
  附件（图、谱、PDF）；目录是能容纳成长的容器，单文件会反复撞墙。
- **资产有家了**：旧布局里 `assets/` 从未被定义清楚（全局共享？每笔记？无代码引用、
  从未创建）。目录化后"资产的归属"问题消失——就放笔记自己家里。
- **所有既有不变量原样保留**：目录名 = 稳定 id = 排序键（时间戳前缀）；`.bak` 写前
  备份单层可回滚（位置从顶层兄弟文件移到目录内 `note.md.bak`）；原子写；front-matter
  schema；`safeResolve` 防穿越。ADR-0005 的"文件系统契约零变化"指 Python→TS 移植期，
  对当时的扁平契约成立，本 ADR 是其后的独立演进。
- **统一形态，拒绝混合**：火花/习惯类笔记也用目录（多一层 mkdir 的成本可忽略）；
  单文件/目录双形态会让 save/find/restore/迁移永久维护两条代码路径。

## 边界（刻意不做）

- **资产摄入流程**：文件怎么进笔记目录（手动放 / git / 未来工具化）不在本 ADR 范围；
  工具面（note_*）对目录内 note.md 以外的文件零感知。
- **检索只索引 note.md**：find_candidates / list_recent 不扫目录内附加文档——等真实
  使用证明需要再说。
- **无迁移工具化**：一次性迁移脚本（`.scratch/migrate_notes_to_dirs.mjs`）已把 18 条
  真实笔记与 smoke 目录搬到新布局，脚本不进 src/。

## 落地核对（2026-08-20）

- `notelib.ts`：`NOTE_DOC='note.md'` 常量；`makeFilename`→`makeNoteDirName`（去 `.md`）；
  `iterNotes` 扫顶层目录（跳隐藏目录如 `.git`、无 note.md 或解析失败的杂散目录静默跳过）。
- `save.ts`/`restore.ts`：id→`<id>/note.md` 解析；`.bak` = 目录内 `note.md.bak`；更新只
  重写 note.md，兄弟文件原样保留（契约测试断言）。
- 契约测试 92 条全绿（原 88 + 目录化新用例：兄弟文件保留、孤儿备份目录/隐藏目录/杂散
  文件忽略）；真实 notes/ 迁移后 listRecent 18 条可见、更新→回滚闭环逐字还原。
